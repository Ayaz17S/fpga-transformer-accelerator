# microGPT FPGA accelerator — RTL

SystemVerilog RTL for a ~4,192-parameter GPT-style Transformer on the PYNQ-Z2
(`xc7z020clg400-1`). Numeric rules (formats, rounding, test-vector files) are
in the shared contract doc.

## Status

The whole model runs on the core (`rtl/gpt_core.sv`): one token in, 27
logits and the argmax next token out, bit-exact against the Python reference
(`GptFx` in `scripts/fixedpoint.py`). `rtl/generator.sv` wraps it for greedy
autoregressive generation (each prediction fed back in until BOS or 16
tokens), matching `generate_fx()` token for token. Weights are placeholders
until the trained model arrives.

| Measure (Artix-7 synthesis, 100 MHz) | Value |
| --- | --- |
| Cycles per token | 3,965 at position 0 → 4,625 at position 15 (40–46 µs) |
| LUTs / FFs | 1,682 / 911 |
| DSP48E1 | 4 |
| Block RAM | 4 × RAMB36 (weights) + 4 × RAMB18 (tables, KV cache) |
| Worst slack | +2.75 ns |

## Layout

| Folder | Contents |
| --- | --- |
| `rtl/` | Synthesizable design: `model_pkg.sv` (dimensions + weight memory map), `mac.sv`, `requant.sv`, `matvec.sv`, `weight_rom.sv`, `embed.sv`, `lut_rom.sv`, `rmsnorm.sv`, `softmax.sv`, `attention.sv` (with the KV cache), `gpt_core.sv` (buffers + controller: the whole model), `generator.sv` (autoregressive loop) |
| `tb/`  | Self-checking testbenches, one per unit, plus `tb_pkg.sv` (shared reference functions) |
| `data/` | ROM images and lookup tables (`.mem`), and test vectors generated by the Python reference |
| `scripts/` | `fixedpoint.py`: bit-exact Python reference shared with the ML side · `gen_luts.py`: lookup tables · `gen_rmsnorm_vectors.py`, `gen_attention_vectors.py`, `gen_model_vectors.py`: test vectors · `gen_placeholder_weights.py`: random weights until trained weights arrive |
| `sim/` | `run.bat` plus one source list (`<tb>.f`) per testbench |
| `syn/` | Out-of-context synthesis script (resources + 100 MHz timing) |
| `build/` | Generated by the scripts; safe to delete |

## Run from a terminal (from this folder)

```
python scripts/gen_placeholder_weights.py
python scripts/gen_luts.py
python scripts/gen_rmsnorm_vectors.py
python scripts/gen_attention_vectors.py
python scripts/gen_model_vectors.py
sim\regress.bat
vivado -mode batch -source syn/synth.tcl -tclargs gpt_core xc7a35tcpg236-1
```

`sim\regress.bat` runs every testbench and prints one PASS/FAIL line each;
`sim\run.bat <tb>` runs a single one.

Drop the part argument once Zynq-7000 device support is installed; the
default part is the PYNQ-Z2's.

## Open in the Vivado GUI

A script builds the whole project, with every file in the right role:

```
vivado -mode gui -source syn/create_project.tcl
```

Or, from an already open Vivado: Tools → Run Tcl Script… → pick
`syn/create_project.tcl`. The project is created in `vivado/` (git-ignored)
and rebuilt from scratch each run; the files you edit stay in `rtl/` and `tb/`.

- Design sources: everything in `rtl/` plus the `.mem` files from `data/`.
- Simulation sources: everything in `tb/`. To pick a testbench, right-click it
  under Simulation Sources → Set as Top, then Run Simulation → Run Behavioral
  Simulation. The Tcl console prints PASS or FAIL.

Expected noise in the Tcl console, safe to ignore:
- `[Board 49-26] cannot add Board Part ...`: board files for device families
  that are not installed.
- `[Wavedata 42-489] Can't add object ... vec_x / vec_h`: the testbench's
  test-vector arrays are too large for the waveform; the DUT's signals are
  still added. Expand `dut` in the Scope pane to look inside a unit.

(Launching the simulation from `vivado -mode batch` fails with
`Spawn failed`, but from the GUI it works; `sim\run.bat` works too.)
