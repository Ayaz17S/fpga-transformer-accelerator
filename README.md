# microGPT FPGA accelerator — RTL

SystemVerilog RTL for a ~4,192-parameter GPT-style Transformer on the PYNQ-Z2
(`xc7z020clg400-1`). Numeric rules (formats, rounding, test-vector files) are
in the shared contract doc.

## Status

The whole model runs on the core (`rtl/gpt_core.sv`): one token in, 27
logits and the argmax next token out, bit-exact against the Python reference
(`GptFx` in `scripts/fixedpoint.py`). `rtl/generator.sv` wraps it for greedy
autoregressive generation (each prediction fed back in until BOS or 16
tokens), matching `generate_fx()` token for token. The weights are the trained
golden-reference checkpoint (`data/checkpoint/`, seed 42, quantized to Q2.14):
and BOS generates `anan`, as in the float64 reference.

Accuracy of the bit-exact model (the RTL) against float64 on the reference's
full held-out set (30,869 names, 219,838 predicted tokens;
`scripts/eval_heldout.py`):

| Measure | Value |
| --- | --- |
| Top-1 agreement with float64 | 99.966% (219,764 / 219,838) |
| Disagreements | 74, all near-ties: largest float64 top-2 margin 0.0024, none above 2x the logit error |
| Max / mean per-token logit error | 0.023 / 0.003 |
| Token-mean NLL | 2.367210 fixed vs 2.367208 float64 (delta +0.000002) |

| Measure (synthesis on xc7z020, 100 MHz) | Value |
| --- | --- |
| Cycles per token | 3,965 at position 0 → 4,625 at position 15 (40–46 µs) |
| LUTs / FFs | 1,682 / 911 (3.2% / 0.9% of the chip) |
| DSP48E1 | 4 |
| Block RAM | 4 × RAMB36 (weights) + 4 × RAMB18 (tables, KV cache) |
| Worst slack | +2.73 ns |

## Layout

| Folder | Contents |
| --- | --- |
| `rtl/` | Synthesizable design: `model_pkg.sv` (dimensions + weight memory map), `mac.sv`, `requant.sv`, `matvec.sv`, `weight_rom.sv`, `embed.sv`, `lut_rom.sv`, `rmsnorm.sv`, `softmax.sv`, `attention.sv` (with the KV cache), `gpt_core.sv` (buffers + controller: the whole model), `generator.sv` (autoregressive loop), `axi_gpt.sv` (AXI4-Lite registers), `axi_gpt_top.v` (Verilog shell for the block design) |
| `tb/`  | Self-checking testbenches, one per unit, plus `tb_pkg.sv` (shared reference functions) |
| `data/` | ROM images and lookup tables (`.mem`), and test vectors generated by the Python reference |
| `scripts/` | `fixedpoint.py`: bit-exact Python reference shared with the ML side · `gen_luts.py`: lookup tables · `gen_rmsnorm_vectors.py`, `gen_attention_vectors.py`, `gen_model_vectors.py`: test vectors · `eval_heldout.py`: fixed point vs float64 on the held-out set � `import_checkpoint.py`: quantizes the trained checkpoint into `data/weights_all.mem` and checks it against a float64 forward pass � `gen_placeholder_weights.py`: random weights, for tests that need no checkpoint |
| `sim/` | `run.bat` plus one source list (`<tb>.f`) per testbench |
| `syn/` | `synth.tcl`: out-of-context synthesis of one module · `create_project.tcl`: Vivado GUI project · `build_overlay.tcl`: Zynq block design → bitstream |
| `overlay/` | The built PYNQ overlay (`gpt_overlay.bit` + `.hwh`) and its timing/utilization reports |
| `host/` | `gpt_overlay.py`: runs the accelerator from Python on the PYNQ-Z2 (`--check` verifies all 27 generations) � `golden_generations.json`: the expected generations, written by `gen_model_vectors.py` |
| `build/` | Generated by the scripts; safe to delete |

## Run from a terminal (from this folder)

```
python scripts/import_checkpoint.py
python scripts/gen_luts.py
python scripts/gen_rmsnorm_vectors.py
python scripts/gen_attention_vectors.py
python scripts/gen_model_vectors.py
python scripts/eval_heldout.py --stride 20   # drop --stride for the full set (~2 min)
sim\regress.bat
vivado -mode batch -source syn/synth.tcl -tclargs gpt_core
```

`sim\regress.bat` runs every testbench and prints one PASS/FAIL line each;
`sim\run.bat <tb>` runs a single one.

## Open in the Vivado GUI

A script builds the whole project, with every file in the right role:

```
vivado -mode gui -source syn/create_project.tcl
```

Or, from an already open Vivado: Tools → Run Tcl Script… → pick
`syn/create_project.tcl`. The project is created in `vivado/` (git-ignored)
and rebuilt from scratch each run; the files you edit stay in `rtl/` and `tb/`.

- Design sources: everything in `rtl/` plus the `.mem` files from `data/`.
- Simulation sources: everything in `tb/`. To pick a testbench, right-click it
  under Simulation Sources → Set as Top, then Run Simulation → Run Behavioral
  Simulation. The Tcl console prints PASS or FAIL.

Expected noise in the Tcl console, safe to ignore:
- `[Board 49-26] cannot add Board Part ...`: board files for device families
  that are not installed.
- `[Wavedata 42-489] Can't add object ... vec_x / vec_h`: the testbench's
  test-vector arrays are too large for the waveform; the DUT's signals are
  still added. Expand `dut` in the Scope pane to look inside a unit.

(Launching the simulation from `vivado -mode batch` fails with
`Spawn failed`, but from the GUI it works; `sim\run.bat` works too.)

## Run on the PYNQ-Z2

Build the overlay (block design → bitstream, about 10 minutes):

```
vivado -mode batch -source syn/build_overlay.tcl
```

It writes `overlay/gpt_overlay.bit`, `overlay/gpt_overlay.hwh` and the
post-route reports. Current build, full overlay including the AXI
interconnect, after place and route at 100 MHz:

| Measure | Value |
| --- | --- |
| LUTs / FFs | 2,056 / 1,449 (3.9% / 1.4%) |
| DSP48E1 | 4 |
| Block RAM | 4 × RAMB36 + 4 × RAMB18 |
| Setup / hold slack | +1.44 ns / +0.05 ns (met) |
| Accelerator address | `0x40000000` (4 KB), cell name `gpt` |

On the board, copy `overlay/gpt_overlay.bit`, `overlay/gpt_overlay.hwh`,
`host/gpt_overlay.py` and `host/golden_generations.json` into one folder, then:

```
sudo python3 gpt_overlay.py --check   # PASS if all 27 generations match the Python model
sudo python3 gpt_overlay.py --all     # prints each generation with cycles and latency
```

The register map is documented at the top of `rtl/axi_gpt.sv`.
